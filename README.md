# qBittorrent Adder (Firefox)

A Firefox-only WebExtension that finds magnet links and direct `.torrent` URLs on webpages and adds an
unobtrusive **Add to qBittorrent** button beside each one. Nothing is submitted until you click a
button. All qBittorrent communication, credentials, and history remain in the extension's privileged
background context.

## Features

- Detects magnet links (`urn:btih:` and `urn:btmh:`) in anchor `href` attributes.
- Detects http(s) URLs whose path ends in `.torrent` (case-insensitive), including query strings and
  fragments. The complete URL is submitted.
- Detects magnet URIs in configurable HTML attributes and configurable element text (for example
  `<code>` blocks).
- Watches dynamically added/changed content with `MutationObserver`; only new subtrees are scanned.
- Injects buttons in a Shadow DOM so host-page CSS cannot leak into or override the UI.
- Shows sending/success/failure states, an accessible live status, and retry after failure.
- Validates the qBittorrent session before each submit, logs in when needed, and retries once if the
  session expires between validation and submission.
- Supports qBittorrent CSRF protection by rewriting Origin/Referer only for the extension's own
  background API requests to the configured host.
- Optional local submission history with duplicate detection, disable/enable behavior, and clearing.
- Opt-in debug logs that never include credentials, cookies, authorization headers, or full URLs.
- No telemetry, analytics, cloud sync, or third-party requests.

## Requirements

- Firefox 140 or newer.
- qBittorrent Web UI enabled and reachable from Firefox.
- The `.torrent` URL must also be reachable **from qBittorrent's network environment**. The extension
  never downloads the torrent file itself.

## Where is the unpacked extension?

The loadable extension is:

```
dist/firefox
```

Load it with **`about:debugging` → This Firefox → Load Temporary Add-on…** and select
`dist/firefox/manifest.json`. The `dist/firefox` directory is generated by `npm run build` and is
already present in a working checkout. You do **not** need `node_modules` or a build to use it.

Temporary add-ons stay loaded until Firefox closes, but you can reload them from `about:debugging`.

## Setup

1. Open the extension settings (toolbar icon → **Open settings**).
2. Enter the qBittorrent base URL, for example `http://192.168.1.10:8080`. Include a reverse-proxy
   path if you use one, for example `https://example.net/qbt`.
3. Enter the Web UI username and password.
4. Click **Test connection**.
5. Save the settings.
6. Open a page with a magnet or `.torrent` link and click the small blue button next to it.

The extension uses qBittorrent's Web API:

- `POST /api/v2/auth/login` to establish a session when needed.
- `GET /api/v2/app/version` to validate the current session before each submission.
- `POST /api/v2/torrents/add` with the URL in the `urls` field for both magnets and `.torrent` URLs.

### Firefox version and manifest

This extension is Firefox-only and uses **Manifest V2** intentionally. Firefox has not announced
MV2 deprecation, and MV2 install-time host permissions are required for direct background requests
to qBittorrent instances on private LAN addresses. Firefox 160's Local Network Access checks block
the equivalent MV3 background requests, even after runtime host permissions are granted, and there
is no extension permission that grants LNA access.

No tabs, page contexts, about:config changes, or helper applications are used. Requests go directly
from the extension background page to qBittorrent.

### qBittorrent Web UI / CSRF settings

The extension works with qBittorrent's default CSRF protection enabled. It does not disable or bypass
authentication. For its own background API requests only, it sets:

- `Origin: <configured qBittorrent origin>`
- `Referer: <configured qBittorrent base URL>/`
- `Sec-Fetch-Site: same-origin`

This makes the request look same-origin to qBittorrent's CSRF check, which compares the request's
origin with the target host. Normal tab requests are never modified. Authentication requires the
configured username/password.

If qBittorrent is behind a reverse proxy, use the same public URL and path in the extension and make
sure the proxy preserves `Host`/`X-Forwarded-*` headers as required by qBittorrent.

### Network note for `.torrent` URLs

When you submit a `.torrent` URL, qBittorrent downloads the file. A URL that works only in your
browser (for example, one requiring browser-only cookies or a VPN on this machine) may fail. Prefer
magnet links or URLs publicly reachable from qBittorrent.

## Permissions

| Permission | Why |
| --- | --- |
| `storage` | Settings, credentials, and optional history stored locally. |
| `cookies` | Reads qBittorrent's HttpOnly session cookie so it can attach it to the extension's own background API requests. |
| `webRequest`, `webRequestBlocking` | Sets Origin/Referer and the session cookie only for the extension's own background requests to the configured qBittorrent origin so CSRF/SameSite handling accepts them. |
| `<all_urls>` (MV2 host permission) | Finds links on webpages and lets the background contact the configured qBittorrent host. The content script never receives credentials and does not transmit page data. |

Credentials are stored with `browser.storage.local`, not `storage.sync`. They are readable by
extension pages/background but are never sent to content scripts or webpages. No data leaves your
machine except requests to your configured qBittorrent server.

## Privacy

- No telemetry, analytics, ads, or external services.
- The extension does not fetch torrent files or follow magnet links in the browser.
- Debug logging is off by default. When enabled, logs contain only operation names, host-safe
  statuses, and HTTP status codes. Passwords, cookies, authorization headers, full URLs, and query
  strings are never logged.
- History stores a SHA-256 fingerprint plus a sanitized name and URL. Query strings and magnet
  trackers are not stored in the displayed history entry.

## Development

### Architecture

```
src/
  manifest.json             Firefox Manifest V2 manifest
  background/
    index.js                 privileged message router, settings/history orchestration
    qbittorrent.js           Web API client, session login/validation, error mapping
    header-rewrite.js        CSRF Origin/Referer compatibility for background requests
    dev-reload.js            optional loopback polling -> runtime.reload()
  content/
    index.js                 content-script entry point
    scanner.js               DOM scanning, shadow-DOM buttons, states, MutationObserver
  shared/
    urls.js                  magnet/.torrent parsing/validation, safe descriptions
    settings-schema.js       defaults, validation, sanitization
    settings-store.js        storage.local helpers
    history.js               fingerprints, sanitized history entries
    display.js               per-hostname display rules
    messages.js              message type constants
    logger.js                opt-in safe logger
  popup/                     toolbar popup (toggle, status, settings shortcut)
  options/                   settings, test connection, history, site rules
tests/                       Vitest unit/integration tests
dev/reload-server.mjs        dependency-free development reload endpoint
build.mjs                    esbuild + static asset build
```

### Tests

The suite covers:

- `btih` and `btmh` magnet parsing, complete URI preservation, trackers/query parameters.
- `.torrent` detection with uppercase suffixes, query strings, fragments, and scheme validation.
- duplicate scanning/buttons, dynamic DOM additions, custom attributes, text selectors, per-site
  hiding, history duplicate states, success/failure/retry states.
- settings normalization/sanitization and credential validation, including ensuring credentials are
  not included in public settings.
- mocked qBittorrent login/session/add flows, expired-session retry, wrong credentials, CSRF/401/403,
  415/404/5xx, `Fails.` responses, network errors, and timeouts.
- history fingerprints and token-free display values.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| **Timed out** / **Cannot reach qBittorrent** | Check base URL/port. On Firefox 160+, add the qBittorrent host/IP to `network.lna.skip-domains` (see above) or use a localhost bridge. Confirm the Web UI is enabled. |
| **401 Unauthorized** on login | Check username/password. qBittorrent may have banned the IP after failed attempts; wait for the ban period. |
| **403 Forbidden** | Session/login problem, IP ban, or Web UI access restrictions. Verify qBittorrent's Web UI logs. |
| **404** | The base URL is wrong or the reverse-proxy path is missing. |
| **Fails.** from qBittorrent | The URL may be malformed, already queued, or unreachable from qBittorrent. |
| No buttons appear | Check the master toggle, per-site rule, and detection settings. Reload the page after changing settings. |
| Settings fields blank on reopen | Load the extension from `dist/firefox` (not `src/`) and use the latest build. The options page reads credentials from the background storage, which persists locally. |
| Private `.torrent` URL fails | qBittorrent must be able to download it; browser-only cookies/VPN-only access won't work. |
